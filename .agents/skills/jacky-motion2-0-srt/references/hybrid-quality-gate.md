# 混合版质量门：稳定运行时 + 强审美模板感

目标：保留 2.1 的稳定装配体系，同时恢复 2.0 的发布会级画面判断。L01-L10 是结构骨架，不是成片设计；风格 CSS 是材质和 token，不是审美完成。每个 beat 必须在骨架之上做出该风格的“可识别场面”。

## 1. 混合版边界

- 保留：`base-template.html`、声明式 step、TL 注册表、L01-L10、validator、browser check。
- 恢复：风格 DNA、composition contract、主视觉占比、强定格帧、坏模式禁令、step 视觉演示。
- 禁止：只把 L 骨架换皮、只改颜色字体、只写通用 fade/stagger、只生成能跑但不好看的 smoke test。

## 2. 每页必须先过 composition contract

```md
composition:
  layout_skeleton: L01-L10 / LX-...
  style_scene: 这页一眼属于哪个风格，靠什么识别
  primary_box: 主视觉相对位置和边界
  secondary_box: 辅助信息相对位置和边界
  anchor_axis: left / right / top / centerline / diagonal / full-width
  negative_space_role: 推进方向 / 对比缓冲 / 记忆定格 / 截图安全
  attention_ratio: 主视觉 45%-65%，辅助 20%-35%，标签 5%-15%，装饰 0%-5%
  numbering_roles: 装饰章节号 / 流程编号 / folio 是否各自清楚，不混用
  final_frame: 最后一帧作为封面是否成立
```

没有 `style_scene` 或 `final_frame`，不进入 HTML。

## 2.1 发布会级版式 harness（强制）

`web-video-presentation` 出片稳定的原因不是样式多，而是每一步先是一个
舒展的整屏构图，再叠加主题。Jacky Motion 生成 HTML 时也必须先过这个
harness：

1. **一页不是 dashboard**：每个 beat 最多 2 个大信息区（primary /
secondary），第 3 个只能是标签、编号、来源或短注释。超过 2 个大区，
先拆 step 或换 L06，不许继续加卡片。
2. **主视觉先占地**：primary 必须占画面注意力 45%-65%，并有可描述的
边界（大标题块 / 大数字 / 大截图 / 大证据 / 大框架图）。如果主视觉只是
一堆同权重小卡片，判定失败。
3. **先定网格，不临场摆放**：每页从 12 栏 / 6 行的隐形网格出发，只选
一种主构图：7:5 左主右辅、5:7 左辅右主、上锚点下展开、全宽轴线。
注释和焦点标记可 absolute，主体模块不可随机 absolute。
4. **留白要有方向**：必须保留一条 20%-30% 的负空间走廊，用于推进、
对比缓冲或最终定格。四周空一圈、中间挤一团，判定失败。
5. **最终帧对象预算**：Claim ≤2 组；Contrast = 2 面板 + 分隔/焦点；
Path = 3-5 节点 + 独立连线轨道；System = 1 锚点 + 2-3 层；Evidence =
1 主证据 + 1 标注 + 1 结论。超预算先分 beat。
6. **卡片不是默认答案**：卡片只用于承载信息对象，不能把整屏包进一个
大卡片，也不能卡片套卡片。多卡同亮、同尺寸、同权重，判定为 PPT 化。
7. **风格元素收敛到一个场面**：纹理、光场、贴纸、标注、规则线等只服务
一个主视觉，不许四处撒装饰。去掉文案后仍应能看见一个明确的场面，而
不是一堆素材。
8. **红框/调试框禁用**：不得用醒目的外框证明“这里是版面区域”。边界
应由对齐、留白、材质和层级自然形成。
9. **编号角色先分层**：章节装饰号只做低权重空间锚点，流程编号只服务
条目识别，folio 只做导航。三者不得共用同一种大小、颜色、位置逻辑；
装饰号压线时只能调整装饰号或规则线，不能改成流程编号样式。

写 beat HTML/CSS 前，先在心里完成这张版式地图：

```md
scene_map:
  primary: 位置 / 尺寸 / 为什么是第一眼落点
  secondary: 位置 / 尺寸 / 为什么不抢主视觉
  negative_space: 留白方向和作用
  object_budget: 最终帧对象数量
  numbering_map: 编号各自语义、位置、和线条安全距离
  failure_risk: 可能挤压、穿线、堆叠的位置
```

答不清，不进入代码。

## 3. 风格 DNA 必须显性出现

每个 beat 至少使用 1 个所选风格的签名组件或签名构图；核心 beat 至少 2 个。

| 风格 | 必须保留的场面感 |
|---|---|
| apple-tech-gradient | 黑色空间、单一暖光/白光焦点、少量玻璃层、概念浮出或让位 |
| finance-studio-cards | 顶部栏/主 KPI/传导链至少两项；主亮次暗，不能全卡同亮 |
| editorial-magazine | 衬线断句、编号/拉引/规则线/裁切图至少两项；留白像编辑判断 |
| newspaper-evidence | 主证据先于结论；来源/日期/编号/引用至少两项；纸张材质至少两种 |
| paper-collage | 厚描边贴纸、硬阴影、胶带/票据/马克笔至少两项；热闹但有网格 |
| sketch-note | 手写字体、墨线框、红笔圈注/SVG 描线；像纸上画出来 |

如果去掉文案后看不出风格，判定失败。
apple-light-blue-glass / ink-framework / manifesto-poster 暂停进入默认推荐和测试闭环；除非用户明确点名，否则不主动选用。

## 4. 版面审美红线

- 一屏一个第一眼落点；不能多个模块同权重。
- 主内容不能挤在中间 40% 区域；留白必须有方向。
- 中文标题按短语断行，每行 4-9 个汉字最稳；禁止单字孤行。
- 行高：hero 1.06-1.18，结论 1.12-1.24，卡片标题 1.18-1.32，正文 1.38-1.6。
- `letter-spacing` 默认 0；禁止负字距。
- 同组元素共享轴线；卡片同组统一高度、内边距、标题基线。
- 核心元素间距 ≥48px；主视觉与外部卡片 ≥64px；主内容距 HUD ≥96px。
- 装饰性大编号与规则线、标题、正文、卡片至少保留 24px 视觉安全距离；
若使用浅色描边号压版，允许靠近但不允许被规则线切穿。

## 5. 坏模式禁令

- 居中大标题 + 三张等宽卡片。
- 中心大圆/光场 + 5-6 个胶囊节点环绕。
- 超大背景圆同时承载标题、说明、节点。
- 左侧大标题，右侧节点随机 absolute 散开。
- 线条靠 rotate 硬连，穿过文字或卡片。
- 截图低透明当背景，或 `object-fit:cover` 裁切信息截图。
- 一屏铺满碎证据、碎卡片、碎贴纸，没有主次。
- 所有 beat 共用一个动画函数，看起来只是模板翻页。

## 6. 从骨架到成片的最低要求

生成 beat CSS 时，必须做三件事：

1. 明确主视觉尺寸和边界，不依赖默认 `.card` 平铺。
2. 用风格签名类或新增该 beat 的风格化结构，让画面有记忆点。
3. 写出最终定格帧的状态；动画只从这个终态反推。

L 骨架只保证不乱；风格成片要靠 beat CSS 和 TL 完成。

## 7. 交付前风格截图门

至少截：首屏、最密 beat、一个多步最终态、收束页。

每张截图问：

1. 第一眼落点是否明确？
2. 去掉文案后是否仍能识别风格？
3. 画面是否像一张可发布的短视频关键帧，而不是能跑的 HTML demo？
4. 是否存在真实重叠、中心堆积、文字压扁、线穿卡、截图不可读？

任一为否，先改版式和 beat CSS，不先调动画。
