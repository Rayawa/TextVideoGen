# 视觉验收检查（Phase 5）

交付前逐条检查，不通过就修复后重新截图。修复优先级：先改版式骨架 → 再改网格容器 → 再改字号文案 → 最后才调动画。

## A. 内容与结构

1. 每个 beat 只有一个核心信息，归入 Claim/Contrast/Path/System/Evidence
2. beat 总数符合主轨预算；没有一句话一页、自然段一页
3. `data-layout` 全部来自登记表；`data-steps` 与真实 `data-step` 元素一致
4. Contrast/Path/System/Evidence 有 `data-visual-demo` 且是真实视觉演示，不是文字显隐
5. 屏幕文字短于口播；普通 motion beat 无剪辑提示词泄漏，只有正式 B-roll beat 显示 `B-ROLL` 与具体小标题
6. 无捏造的数据、来源、引用
7. 每个可见文字都有 `data-text-ref`，值与 content manifest 完全一致；无模型临时补充的标签、按钮、Logo 或解释句
8. `image`/`hybrid` 的图片都存在且实际可见；content manifest 中没有 generated-but-unused 资产

## B. 风格一致性

1. 全篇单一风格；颜色、字体、卡片材质、运动节奏都来自同一风格层
2. beat CSS 没有硬编码 hex 颜色和字体名（token 抽查）
3. 首屏建立了该风格的视觉锚点；去掉文案仍能认出风格
4. 遵守所选 styles/{id}.md 的禁忌清单
5. 无 AI 指纹：紫粉渐变、彩色左边框、emoji、居中标题+三卡、随机散点
6. 无归藏 Swiss 语言：IKB 蓝、柠檬黄、点阵网格、Helvetica 海报巨字组合
7. 默认只验收 6 个重点风格：apple-tech-gradient / finance-studio-cards / editorial-magazine / newspaper-evidence / paper-collage / sketch-note
8. 每个 beat 至少有 1 个风格签名组件或签名构图；核心 beat 至少 2 个
9. L 骨架没有被当成最终设计：每页都有 `style_scene` 对应的场面感和可截图定格帧

## C. 版面与排版（截图上核）

1. 字号下限：hero 标题 ≥96px（纯文字页 ≥120px）、正文 ≥25px、标签 ≥18px
2. 每屏一个第一眼落点；主视觉占注意力 45%-65%；缩到 50% 仍知道这页讲什么
3. 主内容不挤在中心 40% 区域；留白有方向，不是四周空一圈中间一团
4. 核心元素间距 ≥48px；主视觉与外部卡片 ≥64px；主内容距底部 HUD ≥96px
5. 无压字、遮挡、裁切、溢出 stage
6. 中文标题短语断行、无单字孤行；行高符合阶梯（hero 1.06-1.18 / 正文 1.38-1.6）；无负字距
7. 同组元素共享轴线；卡片同组统一高度和内边距
8. 无"中心大圆 + 5-6 胶囊环绕"坏模式；多项并排是 L06 网格
9. 最终定格帧像一张成立的发布会画面
10. 去掉动画只看最终帧，仍然不是普通 PPT 骨架换皮
11. 每屏最多 2 个大信息区；第 3 个只能是标签、来源、编号、短注释。三个以上大块同屏并列，直接失败
12. 主体模块不能随机散落；能画出统一左轴、右轴、中轴或全宽轴线。轴线说不清，判为拼贴
13. 卡片不能成为默认版式：无整屏大卡片包内容、无卡片套卡片、无多张卡片同亮同权重
14. 负空间承担功能：推进方向、对比缓冲或记忆定格。没有功能的空白不算高级留白
15. 不出现红框/调试框/醒目外框来标记版面区域；边界必须由对齐、留白、材质和层级形成
16. 编号语义清楚：章节装饰号、流程/清单编号、folio 三者不能长得像同一种东西。章节装饰号可以大而浅、离正文远；流程编号必须贴近条目；folio 只能低权重导航。
17. 装饰号不得压线、压字、压卡片。发现压线时，先缩小/上移/换角落/缩短规则线，保留原语义；禁止把章节装饰号直接改成流程编号样式来规避问题。

## D. 线条与截图

1. 流程线在独立轨道/SVG 层，不穿文字卡片；连线端点离节点外框 ≥24px
2. 径向外围节点 ≤3；连线无交叉后穿主信息区
3. 信息截图完整清晰，无 cover 裁切、无低透明背景、无文字压图
4. 规则线不穿过任何数字、标题或正文。若线条与装饰号故意形成压版关系，必须有明显留白分隔，不能出现笔画被线切开的视觉结果。

## E. 动画与交互（实际点一遍）

1. 动画服务信息理解；attention path 清楚：第一眼 → 推进 → 定格
2. 核心 beat 有四段式镜头：视觉重心入场 → 画面重构 → 关键信息推进/远近变化 → 记忆定格
3. `reconstruct` 必须表现关系变化，不是卡片淡入；Claim 页省略时要有明确理由
4. `push` 必须能看出当前焦点被推近，非焦点退后/降亮/轻 blur，而不是所有信息同亮
5. `lock` 是一次性记忆定格，结束完全静止，无循环 pulse
6. 核心 beat 有签名 TL，不是全片默认入场；不同 beat 主导动作不同
7. easing 是 expo.out/back.out 体系，无 linear；关键结论前有悬停
8. step 推进只动新增内容；已出现内容稳定；无整页重播
9. 每步新增 1-3 个信息对象；列表逐项揭示，无同时 stagger 涌入
10. 每步结束停在稳定画面：无残留 blur/半透明/transform 错位
11. 动画总时长 < 口播时长（中文 4 字/秒）
12. 点击准备层后倒数 3 秒并自动播放；Space 暂停/继续；←/→ 跳 5 秒；R 从头重播；F 全屏可用
13. 断网打开（GSAP 加载失败）时第一屏静态内容仍可读

## F. SRT 同步与 B-roll

1. 每个 beat 都有合法的 `data-start-ms` / `data-end-ms`，按 DOM 顺序严格递增且不重叠
2. 相邻 beat 空档 ≤500ms；首 beat 覆盖首条 cue，末 beat 覆盖末条 cue
3. 多步 beat 的 `data-step-times` 数量等于 `data-steps - 1`，严格递增并落在 beat 时间内
4. step 切换钉在语义触发 cue，不是机械平均分配
5. B-roll beat 使用 `data-kind="broll"`、`LX-BROLL`、非空 `data-broll-title` 和完整 `.broll-frame`
6. B-roll 小标题 4-18 个字符，具体说明录制对象或动作；无“待补/这里放/适合插入”等制作废话
7. 播放途中切到后台 5 秒再回来，画面追到当前绝对时间，不从旧 step 继续
8. 暂停 5 秒再继续，时间轴不漂移；连续三次 `R` 重播的切换点一致
9. 到末条字幕结束后停在最后定格帧，不循环、不跳回开头
10. HTML 不含音频、TTS 或语音合成代码；SRT 文本不作为逐句字幕显示
11. 相邻 beat 的 motion signature 不重复；连续段落存在稳定的 continuity object，而不是同一套入场反复播放
12. 除有明确语义理由的 `semantic-cut` 外，转场为 350–800ms 的 crossfade/shared-object/camera/hold，无瞬间空白或突变翻页

## G. 校验脚本

```bash
node <SKILL_ROOT>/scripts/validate-motion-html.mjs path/to/output.html
```

FAIL 修复后重跑；WARN 人工确认。Playwright 可用时必须再跑：

```bash
node <SKILL_ROOT>/scripts/check-layout-browser.mjs path/to/output.html path/to/screenshots
```

## H. 截图验收（必做）

至少截：准备层 / 首屏 / 信息最密集的 beat / 所有多步 beat 的最后一步 / 每种 B-roll 画框 / 收束页。

不通过的典型现象：中间堆一团四周空、信息组无共同轴线像拼贴、标题行距压扁、卡片互压、线穿卡、截图不可读、HUD 遮内容。发现任何真实重叠——主视觉、标题、卡片、光场安全区之间——验收直接失败，不允许解释为"空间层次"，先改版式再重截。
