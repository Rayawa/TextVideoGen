# 信息原语

目标: 先判断口播这一拍在传递哪种信息关系, 再选择版式和动画。不要先想风格或卡片。

每个 beat 必须归入一个主信息原语。若同时命中多个, 只保留最能帮助观众理解口播的那个。

## Claim 判断

用于观点、结论、主张、开场钩子。

- 屏幕任务: 让观众记住一句判断。
- 视觉中心: 超大短句、关键词、单个符号或一个被放大的概念。
- 动画重点: 从模糊语境收束成一句话。
- 禁止: 在同屏放 3 个同权重卡片解释它。

## Contrast 对比

用于误区/正解、过去/现在、普通做法/更好做法。

- 屏幕任务: 让差异一眼可见。
- 视觉中心: 左右或上下两个状态, 其中一个必须明显成为当前焦点。
- 动画重点: 分割、替换、翻转、灰化、拉开距离。
- 禁止: 两边完全等亮, 或中间线穿过文字。

## Path 路径

用于步骤、实践路径、因果链、用户旅程。

- 屏幕任务: 让观众知道从哪里到哪里, 下一步是什么。
- 视觉中心: 3-5 个节点和一条稳定路径。
- 动画重点: 节点逐个点亮, 连接线在 grid 轨道或 SVG 安全层中生长。
- 禁止: rotate 硬连线、交叉线、节点围着中心随机散开。

## System 机制

用于模型、框架、层级、循环、生态关系。

- 屏幕任务: 让观众看懂部分如何组成整体。
- 视觉中心: 一个主结构, 辅助节点只解释关系。
- 动画重点: 从单点展开成结构, 或从散点归组为系统。
- 禁止: 所有节点同权重、线条穿过主信息区。

## Evidence 证据

用于案例、截图、引用、新闻、数据支撑。

- 屏幕任务: 让观众相信一个结论。
- 视觉中心: 主证据最大, 结论或标注贴近证据。
- 动画重点: 证据先出现, 标注再落位, 最后锁定结论。
- 禁止: 把截图当低透明背景, 或编造数据/来源/引用。

## 选择顺序

1. 这句话是在下判断吗? 是则优先 Claim。
2. 这句话的核心是两个状态的差异吗? 是则 Contrast。
3. 这句话有明确先后或到达关系吗? 是则 Path。
4. 这句话在解释一个机制如何运转吗? 是则 System。
5. 这句话依赖材料来证明吗? 是则 Evidence。

选不出来时, 说明 beat 太泛, 先改写核心信息或拆 beat。
